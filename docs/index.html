Web Scrapper

A small toolkit for pulling product data off Indian e-commerce sites — a Playwright scraper for Amazon ASINs, a console snippet for Flipkart's compatible-models list, and a local web tool that drives both from your browser.

View on GitHub Quick start

What's in the box

Amazon ASIN scraper

Feed it a spreadsheet of ASINs. It opens each amazon.in/dp/<ASIN> page in a real Chromium window, parses the DOM with BeautifulSoup, and writes one row per product to Excel.

Web tool

All three scrapers behind one local page — Amazon ASINs, Flipkart PIDs, and Flipkart model lists. Paste ids or upload a sheet, watch rows land live, stop a run mid-flight, and download .xlsx or .csv.

Flipkart console snippet

Paste into DevTools on an open "Compatible Mobiles" filter. It scrolls the overlay, collects every model name, and downloads a CSV. No class names, so Flipkart's CSS-hash rotation doesn't break it.

Quick start

git clone https://github.com/pethupraveen/web-scrapper.git
cd web-scrapper

python -m venv .venv
.venv\Scripts\activate          # macOS/Linux: source .venv/bin/activate

pip install -r requirements.txt
playwright install chromium

Run the web tool

python -m webapp        # Windows: run_webtool.bat

Open http://127.0.0.1:8000. One tab for Amazon ASINs, one for Flipkart PIDs, one for Flipkart model lists; results stream in as they're scraped and export to Excel or CSV. Start it without --reload — reload mode puts uvicorn on a selector event loop that can't launch Playwright's browser on Windows.

Run the Amazon scraper from the CLI

Drop an input_asins.xlsx beside the script with an ASIN column, then:

python Amazon_Updated_Script.py

Output goes to scraped_amazon_results.xlsx, one row per ASIN:

  • ASIN
  • Status
  • Title
  • Price
  • Rating
  • ReviewCount
  • Bullets
  • URL

Run the Flipkart snippet

  1. Open a Flipkart listing and open the Compatible Mobiles filter overlay.
  2. Open DevTools (F12) → Console.
  3. Paste console_snippet.js, press Enter, and let it finish scrolling.
  4. compatible_mobiles.csv downloads automatically.

Design notes

Headful on purpose. Chromium launches with headless=False and an en-IN locale — it gets challenged far less often than a headless session.

Paced, not hammered. Two waits per product (2–4s after load, 2–5s between ASINs) keep the request rate close to human browsing.

Fails soft. A blocked or missing page returns Status = "Blocked/Not Found" and an exception returns Status = "Error: …". Either way the run continues and the row is kept, so a single bad ASIN never costs you the batch.

The Flipkart PID URL matters. /product/p/itm?pid=… serves a generic "Itm Store" page that ignores the pid entirely — every id comes back as the same product. /product/p/itme?pid=…, with the trailing e, resolves properly. One character, and it silently corrupts a whole batch rather than erroring.

Prices are scoped to the buy box. The product's own price renders large and high on the page; the "Similar Products" carousel prices are small and far below. Reading the first ₹ in the page text picks up a carousel price whenever the buy box is empty, so the scraper measures font size and position instead — and waits for the buy box to hydrate before reading it at all.

Price selectors are a chain. Amazon serves several price layouts; the scraper tries .priceToPay, then .a-price, then the two legacy #priceblock_* ids, and takes the first one that actually carries text — a matching node with an empty label doesn't end the search.

Excel inputs and outputs are gitignored — the repo holds the code, not the data. Scrape responsibly and within each site's terms of use.
